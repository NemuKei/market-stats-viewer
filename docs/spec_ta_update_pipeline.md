# spec_ta_update_pipeline

## エントリ
- ローカル実行:
  - `python -m scripts.update_ta_data`
- CI:
  - `.github/workflows/update_data.yml` から実行

## 処理フロー（MVP）
1. TA索引ページから年度ページリンクを収集する。
2. 各年度ページで「各社別内訳」Excelリンクを収集し、原本とSHA-256を取得する。
3. 収集した全原本の年度・期間と対応形式を確認する。
4. 下記の変更なし条件を満たす場合は再解析せず終了する。
5. 各Excelを解析し、`fiscal_year` / `period` / `company` / `segment` / `amount` を抽出する。
   会社の合計・小計行は `stats.ta.is_ta_summary_company` で除外する。
6. 全原本から1件以上ずつ会社行を抽出できた場合に、作業コピーの `ta_company_amounts` を再構築する。
7. `data/meta_ta.json` の原本情報・`extractor_version` とDBを一つの保存単位として確定する。
   共通lock・保存失敗時のrollback・中断後の復旧は
   [統計DBとメタデータの保存・復旧](spec_update_pipeline.md#統計dbとメタデータの保存復旧r05) に従う。

## 変更なし判定と抽出器の版
- `scripts/update_ta_data.py` の `EXTRACTOR_VERSION` は `1` とする。
  抽出規則を変え、同じ原本を再解析する必要がある変更ではこの版を更新する。
- 再解析を省略できるのは、次の条件をすべて満たす場合だけとする。
  - 収集した原本の `signature` がメタデータと一致する。
  - メタデータの `extractor_version` が実装と一致する。
  - 既存SQLiteの `ta_company_amounts` から必要な列を読め、1件以上の行がある。
- 版がない・異なる場合、DBまたはテーブルがない場合、テーブルが空または
  読取不能の場合は、原本が同じでも再解析する。
- 変更なしで終了するときはDBとメタデータを更新しない。
  既存の版なしメタデータからの移行は、次の通常更新が全原本の解析に成功した
  時点で行う。このコード変更自体では実データを再生成しない。

## 期間の扱い
- 年度総計は `period=total`。
- 月次は `YYYY-MM` に正規化。

## 失敗時
- 収集した「各社別内訳」原本が1つでも次の状態なら、保存前に例外終了する。
  - 年度または期間を特定できない。
  - 未対応の `.xls` 形式である。
  - Excel解析で例外が発生する。
  - 解析結果の会社行が0件である。
- 年度・期間・形式の確認は変更なし判定の前に行う。分類不能な原本や
  スキップした原本を含む集合を、処理済みの `signature` として保存しない。
- 他の原本の解析が成功していても一部だけでテーブルを置き換えない。
  既知のURLに限らず、同じ期間の新URLや新しい期間の原本にも適用し、
  既存DBとメタデータをそのまま保持する。取得時の例外も保存前に伝播する。
- 表書込・meta保存・ファイル配置の途中失敗でも、共通保存処理が旧DBと旧メタを復旧する。
  プロセス中断後は次の統計更新が変更なし判定より前に未完了保存を復旧する。
- 次回の全原本再解析で未対応・不正な原本が見つかれば更新は停止する。
  原本または対応処理を修正して再実行するまで、直前の保存データを使う。

## 検証
- `python -m pytest tests/test_stats_ta.py tests/test_update_ta_data.py`
- 一時WorkbookとSQLiteを使い、集計行の除外、会社グループ名の保持、
  区分別の金額選択、版変更・テーブル欠落時の再処理を確認する。
- 2期間のうち1原本だけが解析失敗・0行になる場合と、分類不能・未対応形式に
  なる場合に、旧DBと旧メタデータのbytesが変わらないことを確認する。
